\# 05 \- Design System  
\#\# Version 1.0

\> Status: In Progress  
\> Purpose:  
\> Define the visual foundation of the portfolio. Every page, component and animation should follow this system.

\---

\# 1\. Design Philosophy

The design system exists to create consistency.

Consistency creates familiarity.

Familiarity creates trust.

Trust creates conversions.

The system should feel invisible.

Visitors should notice the product.

Never the design system itself.

\---

\# 2\. Layout System

\#\# Grid

Desktop

12 Columns

Tablet

8 Columns

Mobile

4 Columns

\---

\#\# Container

The layout should never feel stretched.

Use generous horizontal margins.

Content width should remain comfortable for reading.

Large screens should gain whitespace rather than wider text blocks.

\---

\#\# Vertical Rhythm

Spacing should follow a predictable scale.

Never create random spacing.

Every section should breathe.

Every component should align with the same rhythm.

\---

\# 3\. Spacing System

8px

Spacing should always use this scale.

Never use arbitrary values.

Whitespace is intentional.

\---

\# 4\. Typography System

Typography is the strongest visual element.

The website should rely on typography before graphics.

\---

\#\# Font Personality

Primary Typeface

Modern

Neutral

Highly legible

Geometric

Minimal

Avoid fonts that feel playful.

Avoid fonts that feel futuristic.

Avoid decorative fonts.

Typography should feel timeless.

\---

\#\# Heading Scale

The relationship between sizes should remain consistent.

\---

\#\# Reading Width

Never allow paragraphs to become excessively wide.

Reading should feel effortless.

\---

\# 5\. Colour System

The interface should remain almost monochromatic.

Primary

White

Secondary

Near Black

Neutral

Multiple Grey Levels

Accent

Single Brand Accent

Accent colour should appear only when guiding attention.

Never decorate with colour.

Projects provide visual diversity.

The interface should remain calm.

\---

\# 6\. Border Radius

Corners should feel engineered.

Not playful.

Recommended system

Small

Medium

Large

Avoid excessive rounding.

Avoid perfectly sharp corners everywhere.

Balance precision with warmth.

\---

\# 7\. Shadows

Shadows communicate hierarchy.

Not decoration.

Rules

Small elevation

Soft shadow

Large elevation

Slightly deeper shadow

Never use harsh shadows.

Never stack multiple dramatic shadows.

Depth should feel natural.

\---

\# 8\. Blur

Blur should communicate depth.

Never style.

Use blur only when:

Navigation floats

Modals appear

Overlay content exists

Avoid blurred cards throughout the interface.

Blur should remain rare.

\---

\# 9\. Buttons

Buttons communicate action.

Primary Button

Strong contrast

Clear hierarchy

Medium radius

Comfortable padding

Secondary Button

Minimal

Border only when needed

Text Button

Used for low emphasis actions

Never create more than two competing primary buttons.

\---

\# 10\. Icons

Icons should feel precise.

Consistent stroke weight.

Minimal detail.

Avoid colourful icons.

Avoid emoji.

Icons support content.

Never become decoration.

\---

\# 11\. Cards

Cards should never feel like floating containers.

Instead

Think of them as carefully arranged surfaces.

Minimal borders.

Minimal elevation.

Generous spacing.

Cards should separate information.

Not create visual noise.

\---

\# 12\. Images

Every image should feel curated.

Consistent aspect ratio.

Consistent corner treatment.

Consistent spacing.

Avoid random crops.

Avoid inconsistent scaling.

Images should feel like products.

Not screenshots.

\---

\# 13\. Forms

Forms should reduce friction.

Large inputs.

Clear labels.

Comfortable spacing.

Visible focus states.

Minimal validation noise.

The user should never feel overwhelmed.

\---

\# 14\. Dividers

Avoid unnecessary divider lines.

Whitespace should perform most separation.

Use dividers only when they improve understanding.

\---

\# 15\. Responsive Philosophy

Responsive design should adapt the experience.

Not simply shrink it.

Mobile users deserve the same quality.

Animation should simplify on smaller devices.

Content hierarchy should remain identical.

Never hide important information simply because the screen is smaller.

\---

\# 16\. Accessibility

The premium experience should also be accessible.

Maintain readable contrast.

Visible keyboard focus.

Reduced motion support.

Large touch targets.

Semantic HTML.

Accessibility is part of quality.

Not an optional enhancement.

\---

\# 17\. Performance Budget

Visual quality should never reduce usability.

Prioritise:

Fast loading

Smooth scrolling

Stable layouts

Responsive interaction

Avoid animations that reduce frame rate.

Every animation must justify its performance cost.

\---

\# 18\. Component Philosophy

Every component should answer one question.

Does this increase trust?

If not...

It probably should not exist.

\---

\# Final Principle

The design system should disappear.

Visitors should remember:

The experience.

The projects.

The confidence.

The craftsmanship.

Never the UI itself.

When someone leaves the portfolio, they should remember solving problems, not rounded corners or button styles.

The interface succeeds when it becomes invisible.
